Exploitation Path Summary

VULNERABILITY CHAIN:
====================

1. MISSING ORIGIN CHECK (CWE-346):
   The iframe registers: window.addEventListener("message", l, false)
   Handler l(e) dispatches on e.data.method WITHOUT checking e.origin or e.source.
   ANY window can invoke any of the 5 handler functions.

2. WILDCARD TARGET ORIGIN (CWE-201):
   ALL outbound postMessage calls use targetOrigin "*":
     window.parent.postMessage({method:"getTcpEmployeeLogin",...}, "*")
     window.parent.postMessage({method:"getFeatureStatus",...}, "*")
     window.parent.postMessage({method:"getAPIGatewayDataFromParent",...}, "*")
     window.parent.postMessage({method:"getCountryCode",...}, "*")
     window.parent.postMessage({method:"publishClientSideMetrics",...}, "*")
     window.parent.postMessage({method:"getDarkModeStatus",...}, "*")
   If an attacker embeds this iframe, they receive ALL of these messages.

3. PROMISE INJECTION (CWE-940):
   Handlers resolve promises using attacker-supplied data:
     function u(e){y[e.guid]&&y[e.guid].resolve(e.responseData)}
   Attacker can inject arbitrary responseData into the app's async data flow.

4. VARIABLE SHADOWING BUG (Defense Weakness):
   function o(e,t,r,n){var a=a();...new Promise(function(a,i){y[a].resolve=a...})}
   The Promise callback parameter "a" shadows the outer GUID "a".
   y[resolve_function].resolve = resolve_function (wrong key)
   y[guid].resolve is NEVER set inside the Promise.
   This means promise resolution via handler responses MAY SILENTLY FAIL,
   but the timeout fallback (setTimeout -> y[a].resolve(b.n)) still works
   because inside setTimeout, "a" = resolve function, so calling it works.

   EXPLOITATION IMPACT OF BUG: The variable shadowing means the guid-based
   promise resolution in handlers (u, d, f, s) may be broken. But this
   actually HELPS the attacker for the dark mode vector (no guid needed)
   and does NOT prevent data exfiltration (Attack 1 still works regardless).

ATTACK SCENARIOS:
=================

A) CLICKJACKING + DATA THEFT:
   Attacker hosts this PoC page, embeds victim iframe.
   User visits attacker page. Iframe loads, sends requests to parent (*).
   Attacker captures: employee login data, API requests, feature flags, metrics.

B) RESPONSE FORGERY:
   As the embedding parent, attacker intercepts all requests and
   auto-responds with forged data. The iframe app processes attacker

   - Fake employee credentials -> locale/role spoofing
   - Fake feature flags -> enable debug/admin features
   - Fake API responses -> corrupt business logic (remittance amounts)

C) UI MANIPULATION (No GUID Required):

   no GUID validation. Any origin can force theme changes.
